# Hotel Analytics — интерактивная система коммерческой аналитики отеля

**Публичная демонстрационная версия веб-приложения для анализа спроса, продаж, загрузки, тарифов и экономического результата гостиницы.**

**[Открыть приложение](https://belyakovko.github.io/hotel-analytics-demo/)** · [Исходный код](https://github.com/belyakovko/hotel-analytics-demo)

> Это **не изображение и не набор статичных экранов**. Приложение запускается в браузере, обрабатывает действия пользователя, фильтрует данные, пересчитывает сценарии и формирует файлы для выгрузки. Все опубликованные данные синтетические. Это самостоятельная портфельная адаптация более сложной системы, а не её полная производственная копия.

## Задача продукта

Объединить разрозненные коммерческие показатели отеля в единый управленческий контур:

**Данные → показатели → отклонения → причины → варианты решений → оценка экономического результата.**

Система спроектирована вокруг решений, а не только отчётности: важно видеть не просто изменение загрузки или цены, а влияние спроса, темпа продаж, доступности номерного фонда и затрат на результат периода.

### Пример работающей бизнес-механики: сценарный расчёт

В модуле **«Планирование»** пользователь изменяет три параметра: изменение цены, изменение объёма до учёта эластичности и коэффициент эластичности. JavaScript немедленно рассчитывает:

1. Новую среднюю цену.
2. Ожидаемый объём продаж с условной реакцией спроса на цену.
3. Маржинальный результат базового и нового сценария.
4. Разницу между сценариями и направление изменения результата.

Упрощённая модель использует принцип:

`Маржинальный результат = Проданные ночи × (Цена − Переменные затраты на ночь) − Постоянные затраты за период`

Это **реальный выполняемый расчёт в демоверсии**, но не производственный алгоритм прогнозирования и не доказанная оценка ценовой эластичности.

### Пример работающей механики: тарифный реестр

Поиск и фильтрация выполняются над массивом тарифов в JavaScript. Выбор строки открывает карточку с периодом проживания, периодом продаж, планом, бронью, темпом продаж, необходимым темпом и сигналом. Расчёт остатка до плана выполняется при открытии карточки. Сами исходные тарифы, темпы и сигналы — демонстрационные.

### Пример работающей механики: экспорт

При нажатии кнопки выгрузки приложение формирует CSV с разделителем `;` и UTF-8 BOM для удобного открытия в Excel. Файл создаётся непосредственно в браузере; сервер и внешнее API для этого не нужны.

## Бизнес-логика, заложенная в структуру

- **Спрос:** уникальный клиент, запрос (`клиент × день`) и расчёт — разные показатели; один расчёт может относиться к нескольким тарифам.
- **Продажи:** ночи, счета, сумма, ADR (`выручка / проданные ночи`) и средний чек (`выручка / счета`) рассматриваются отдельно; отмены не должны вычитаться повторно.
- **Тарифы:** план и текущая бронь сопоставляются с темпом продаж; статус риска помогает определить, где требуется внимание.
- **Номерной фонд:** физическая ёмкость отделяется от коммерчески доступного фонда; ремонт, служебные и бесплатные размещения учитываются отдельно.
- **Прогноз:** будущие продажи и физическая возможность их разместить — разные величины.
- **Экономика:** решение об изменении цены оценивается по маржинальному результату периода, а не только по ADR или загрузке.

Эти принципы отражены в структуре экранов и подписях. **Полная производственная реализация методик в данном публичном репозитории отсутствует.**

## Границы демоверсии

Чтобы корректно оценивать проект, важно различать рабочую интерактивность и полноту производственной системы:

- **Работает:** навигация, фильтры, поиск, выбор периода и даты, открытие карточек, изменение сценария, клиентский пересчёт маржи, экспорт CSV, переключение темы.
- **Демонстрируется на заранее заданных данных:** показатели спроса, продаж, CRM, тарифов, графики, сигналы, доступность и прогнозные значения.
- **Не реализовано в публичной версии:** авторизация, серверные API, база данных, синхронизация с CRM/PMS, запись тарифов, полноценный прогноз, автоматическое выявление конфликтов размещения, согласованный сквозной расчёт всех показателей из единого источника.

Часть агрегатов разных экранов не образует единую сверенную модель данных. Кнопка обновления перерисовывает встроенный набор, а не запрашивает новые данные. Изменение периода в некоторых разделах масштабирует демонстрационные KPI, но не запускает запрос к реальному источнику. Настройки и создание тарифов показаны без сохранения изменений.

## Как проверить, что приложение работает

1. Откройте [демоверсию](https://belyakovko.github.io/hotel-analytics-demo/).
2. В **«Управлении тарифами»** введите часть названия тарифа, выберите категорию и откройте карточку найденной строки.
3. В **«Планировании»** измените три ползунка и сравните маржинальный результат до и после; нажмите **«Сбросить сценарий»**.
4. В **«Спросе»** и **«Продажах»** переключите период день / неделя / месяц.
5. В **«Продажах»** или **«Hotel Advisors»** скачайте CSV и откройте файл в Excel.
6. Переключите тему и проверьте мобильную навигацию.

## Запуск локально

Скачайте репозиторий и откройте `index.html` в современном браузере. Внешние зависимости и установка пакетов не требуются.

## Безопасность данных

В репозитории используются только вымышленные показатели, названия и примеры. Подключения к рабочим системам, реальные сведения о клиентах, ключи API и конфиденциальные данные не публикуются.
