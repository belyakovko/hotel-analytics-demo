# Hotel Analytics · Demo

Самостоятельная публичная демонстрация аналитической системы управления отелем. Все данные синтетические.

**Это не копия исходного приложения и не точная реализация бизнес-расчётов.** Это статический интерактивный прототип интерфейса, который демонстрирует основные модули, визуальную концепцию и управленческую модель.

## Запуск

Откройте `index.html` в браузере. Требуется только HTML + CSS + JavaScript, сборка, сервер, БД и ключи не нужны.

## GitHub Pages

1. Создайте отдельный **публичный** репозиторий, например `hotel-analytics-portfolio-demo`.
2. Загрузите в корень репозитория `index.html`, `styles.css`, `app.js` и `README.md`.
3. Settings → Pages → Deploy from a branch → `main` / `/(root)` → Save.
4. URL будет в виде `https://<username>.github.io/hotel-analytics-portfolio-demo/`.

Не публикуйте реальные данные клиентов, ключи API и конфиденциальные отчёты.

## Разделы

- **Обзор** — ключевые показатели, сравнительные графики, прогноз, месячные карточки.
- **Спрос** — уникальные клиенты, запросы (клиент × день), расчёты, периоды отгрузки и детализация тарифов.
- **Продажи** — ночи, счета, сумма, ADR, средний чек, менеджеры, отдельные отмены.
- **CRM-аналитика** — воронка сделок, состояния качества данных.
- **Управление тарифами** — реестр, фильтры, план, бронь, pickup, сигналы, карточка тарифа.
- **Планирование** — интерактивный учебный сценарий цены, спроса, переменных и постоянных расходов и маржинальности.
- **Номерной фонд** — физические 72 номера (36/26/6/2/2), исключение занятых, бесплатных, ремонтных и служебных.
- **Hotel Advisors** — OTB-таблица и CSV-выгрузка (синтетическая).
- **Настройки / Инфо** — описание принятых принципов и ограничений демонстрации.

## Важные соответствия реальному проекту

- Тёмная бирюзовая палитра и светлая тема ориентированы на `app/globals.css`.
- Структура бокового меню — по `app/dashboard-tabs.tsx`.
- Обзор — по `app/dashboard-overview.tsx`.
- Доступность по физическим номерам — 72 номера с закреплённым распределением из `README.md` исходного репозитория.
- Счета продаж фильтруются в оригинале по `invoice_date`, а не созданию сделки.
- Запрос спроса — клиент × день, а не количество расчётов.
- Текущий оперативный M0 не прогнозирует будущие отмены; фактические отмены уже исключены из текущей брони.
- В исходном проекте сроки продажи определяются **каждым тарифом** отдельно, не единой датой 25-го.

## Границы точности

Все значения вымышлены; агрегаты разных разделов не образуют единого сверенного бухгалтерского набора. Некоторые элементы являются иллюстрациями. Сценарий планирования — упрощённая формула, не эквивалент производственной модели. Экраны производственного интерфейса могут отличаться по мелким деталям от этой адаптации.
